# new-version-multiagent — 이광수 페르소나 챗봇 (파인튜닝 전환)

> 작성: 2026-06-24 · 상태: 계획 합의 완료, 코드 미착수
> 이전 버전(`agents_2/` Gemini RAG)에서 **말투 담당을 RAG → 파인튜닝 모델로 전환**하는 신규 설계.

---

## 1. 목표 & 배경

이광수(춘원) 친일 페르소나 멀티에이전트 챗봇을 발표문 기반 학술 프로젝트로 구축. 기존 파이프라인의 두 가지 실패 원인을 동시에 해결한다.

- ❌ 기존 ①: RAG로 말투 예시를 긁어다 흉내 → 청크가 뒤섞여 모델이 합성하다 헷갈림
- ❌ 기존 ②: 로컬 gemma4(9.8GB) 호출당 10~15분, 풀 파이프라인 47분 → 실사용 불가

→ **해법:** 말투를 모델 가중치에 새겨넣고(파인튜닝), 작은 모델(2.4B)로 로컬 추론을 빠르게.

---

## 2. 아키텍처

```
사용자 질문
   │
   ▼
KnowledgeAgent (RAG, 논문 12편 → 구조화 논거)      ← "내용" 담당
   │
   ▼
StyleModel (파인튜닝 EXAONE-3.5-2.4B)              ← "말투" 담당 (NEW)
   │   현대어 논거 → 이광수 1인칭 친일체로 재서술
   ▼
ValidatorAgent (자기합리화 판정, 최대 3회 재시도)   ← "검증" 담당
   │
   ▼
최종 응답
```

기존 대비 **가운데 Style 칸만 RAG → 파인튜닝으로 교체**. 논문 데이터의 역할(내용 RAG + Validator 루브릭)은 그대로 유지.

## 4. 데이터 3종 — 역할 분리 (섞으면 망함)

| 코퍼스 | 정체 | 역할 |
|---|---|---|
| **친일 에세이** (돌베개·민족개조론·창씨개명·심적신체제·조선의 학도여·황민화와 조선문학·교담록·육장기 등, 이미 PDF) | 1인칭 자기합리화 그 레지스터 | **파인튜닝 말투 gold** ⭐ |
| **전집 소설 21권** (.hwp ×20, .hwpx ×1) | 근대 국어 + 이광수스러움 | 근대어 표면 보강 (인칭 필터링 후) |
| **논문 12편** (GS_paper) | 2차 사료, 인지부조화 분석 | 내용 RAG + Validator 루브릭 |

### 4.1 소설 인칭 필터링 정책 ⭐ (핵심)

소설 텍스트 안의 세 종류를 다르게 취급한다:

| 종류 | 검출 방법 | 처리 |
|---|---|---|
| **1인칭 서술** (자전소설: 그의 자서전 16권, 나 20권 등) | 작품 단위 1인칭 판정 | **SFT gold로 사용** ⭐ |
| **대화** (「」 / 따옴표 안 인물 대사) | 인용부호 검출 | 소량만 실험, 효과 없으면 제외 |
| **3인칭 서술** (narration) | 위 둘 제외한 나머지 | **SFT gold 제외.** 원하면 *라벨 없는 근대어 보강*에만, 싫으면 버림 |

근거: 페르소나 출력 stance는 "1인칭으로 자기를 변호하는" 목소리. 3인칭 서술자 목소리는 stance가 어긋나 gold로 쓰면 페르소나가 흐려짐. 단 3인칭의 어휘·한자어·어미 *표면*은 stance-중립이라 비지도 보강엔 무해.

가중 초안: **에세이 : 소설(1인칭) ≈ 7 : 3** (Phase 1 테스트셋 점수 보며 조정).
어느 권이 1인칭인지는 Phase 0 추출 시 실제 확인.

## 5. 파인튜닝 데이터 생성 (style transfer)

StyleModel의 실제 task = **"중립적·무문체 현대어 → 이광수 친일체로 재서술"**. 학습 쌍도 그 방향(neutral → author).
방법론 참고: 루쉰 문체 ST 논문(2-pass: 대표 문장 추출 → 중립화 → 병렬쌍 학습)을 채택하되 우리 상황에 맞게 조정.

```
1. hwp/hwpx/pdf → 텍스트 추출                         (Phase 0)
2. 분절 + 인칭 필터링(§4.1)                            ← 에세이·1인칭만 gold 후보
3. [Pass A] LLM이 "문체 밀도 높은 대표 문장" 선별        ← 아무 문장 X, 스타일 농도로 거름
4. [Pass B] 각 원본 → "중립·무문체 현대어"로 중립화      ← 쌍의 입력
5. (중립 현대어, 이광수 원본) 병렬쌍 2,000~5,000개
6. hold-out 테스트셋 분리
```

### 루쉰 논문 대비 3가지 조정
| 논문 | 우리 조정 | 이유 |
|---|---|---|
| 에세이당 **3개** 추출 | **하드캡 제거**, 문체 밀도 필터만 유지. volume은 1인칭 소설에서 충당 | 에세이 ~9편뿐 → 3×9=27쌍은 턱없이 부족 |
| 중립화 = 문체만 제거 | 동일 + **논증적 의도·감정 어조 보존을 프롬프트에 명시** ⭐ | 페르소나가 자기합리화(논증적). 수사적 동작까지 학습해야 함 |
| **문장 단위(~100자)** | 대부분 ~100자 문장쌍 + **일부 문단급 쌍 혼합** | 챗봇은 문단급 논거를 재서술 → 응집성도 학습 필요 |

품질관리: 의미 손실 쌍 필터링, 중복 제거. 전체 역번역 대신 **선별 추출**이라 LLM 호출·비용 더 절감(쿼리당 ~$0.002).
중립화 프롬프트 보존 항목: **의미 · 논증적 의도 · 감정 어조** (문체적 특징만 제거).

## 6. 논문 데이터 활용 (말투 아님, 내용+기준)

1. **KnowledgeAgent RAG**: 논문 → **5개 쟁점축 JSON 스키마** 구조화 후 색인. grounding으로 할루시네이션 방지.
   - 5축: (1) 전향의 내적 동인 (2) 자전적 글쓰기 전략 (3) 창씨개명·선도적 협력 (4) 참정권·감성 정치 (5) 허위의식·공범론
2. **Validator 루브릭**: 논문의 인지부조화 분석이 "진짜 이광수식 합리화인가" 채점 기준.

## 7. Validator 재설계 — 말투/합리화 분리 채점

| 축 | 담당 | 방법 |
|---|---|---|
| **말투 충실도** | 파인튜닝 모델 + perplexity | Validator는 가볍게 (또는 자동 측정) |
| **합리화 충실도** | Validator (진짜 일) | 인지부조화 3축(합리화/피해자비난/자기확증) 각 0~N점 + **근거 인용** 구조화 채점 |
| **사실 정합성** | Validator | 검색된 논거와 모순 없는지 체크 |

단일 70점 임계 → 축별 구조화 점수로 전환(더 안정적). 말투 실패가 거의 사라지므로 재시도 루프는 "합리화 깊이 부족"만 잡게 됨.

## 8. 로드맵

| Phase | 내용 | 산출물 |
|---|---|---|
| **0** | hwp→텍스트 추출 검증 (hwp5txt / LibreOffice / PDF 변환 비교; .hwp vs .hwpx 포맷 다름) | 추출 파이프라인 + 1인칭 권 목록 |
